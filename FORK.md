# 3x-ui с входом через OIDC

Форк [MHSanaei/3x-ui](https://github.com/MHSanaei/3x-ui) с входом через OIDC.
Основа кода OIDC: ветка `add-oauth2` из [CRASH-Tech/3x-ui](https://github.com/CRASH-Tech/3x-ui/tree/add-oauth2)
(автор s.kharlamov). Она перенесена на актуальный релиз и доработана.

Панели этого форка получают обновления только из этого репозитория.

## Версии

Версия выглядит как `3.11.0-oidc.1`: номер релиза upstream и номер нашей сборки.
Панель предлагает обновление, когда её версия отличается от последнего релиза форка.

## Перевод сервера с официального 3x-ui

Перед обновлением сохрани базу:

```bash
cp /etc/x-ui/x-ui.db /root/x-ui.db.bak
```

Обновление из этого форка:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/EgorMIX/3x-ui/main/update.sh)
```

## Откат на официальный 3x-ui

```bash
bash <(curl -Ls https://raw.githubusercontent.com/MHSanaei/3x-ui/main/update.sh)
```

Добавленные форком колонки и настройки официальной версии не мешают. Обратно на
форк можно перейти той же командой обновления.

## Настройка Pocket ID

1. Создай OIDC-клиента. Callback URL: `https://<адрес панели>/<базовый путь>/oauth/callback`.
   У каждого сервера свой адрес, поэтому добавь callback каждой панели.
2. Создай группы, например `xui-admins` и `xui-users`.
3. В панели открой «Настройки панели» → OIDC и заполни:
   - URL провайдера: адрес Pocket ID;
   - Client ID и Client secret;
   - Redirect URL: тот же callback. Лучше задать его явно, чтобы он не выводился из заголовков запроса;
   - группа администраторов и пользовательская группа;
   - примечание инбаунда, если пользователям нужны автоматические клиенты.
4. Сохрани настройки и нажми «Войти через SSO» в другом окне, не закрывая текущую сессию.

## Как это работает

- Участник группы администраторов получает полный доступ к панели.
- Участник пользовательской группы получает личный кабинет `/cabinet/` со своим подключением.
- Пользователь вне этих групп не входит.
- Вход по паролю остаётся рабочим. Это запасной путь, если Pocket ID недоступен.
- Панельная 2FA при входе через SSO не запрашивается: подтверждение личности лежит на Pocket ID.
- Клиент привязан к постоянному `sub` из Pocket ID. Смена email не создаёт нового клиента.
- Клиента, созданного вручную, SSO не забирает, даже если email совпал: такой вход будет отклонён.
- Клиенты раз в 5 минут добавляются к инбаундам с указанным примечанием. Если отвязать
  SSO-клиента от такого инбаунда вручную, он вернётся.
- Исключение из группы закрывает новые входы, но VPN-клиент не отключает.
  Удали или выключи его в панели вручную.

## Единое приложение

OIDC должен выглядеть частью 3x-ui, а не вставкой со стороны. При каждом обновлении просмотри,
что нового появилось в upstream, и доведи OIDC до того же уровня:

- **Интерфейс:** новые компоненты, стили и расположение настроек применяй и к вкладке OIDC,
  странице входа и кабинету. Бери готовые компоненты проекта, а не отдельные свои.
- **Вход и доступ:** новые способы входа, роли, права и проверки сессий должны работать и для входа
  через SSO. Панельная функция не должна молча обходиться через SSO.
- **Клиенты:** новые поля и протоколы проверяй на создании, привязке и кабинете.
- **Настройки и секреты:** новые механизмы хранения, скрытия и сброса секретов применяй к `oauthClientSecret`.
- **Переводы:** тексты OIDC должны быть на всех языках, включая новые. Сейчас `sk-SK` использует английский.
- **Документация:** обновляй OpenAPI, README и этот файл, если изменилось поведение.

Если upstream добавил свою встроенную функцию, совпадающую с нашей, переходи на неё и убирай дубль.

## Порядок обновления серверов

Серверы обновляются по одному, мастер всегда последним:

1. менее важная нода;
2. остальные ноды;
3. мастер.

Перед каждым обновлением сохрани базу и после него проверь версию, работу `x-ui` и Xray,
количество инбаундов и клиентов, статус нод и реальное VPN-подключение.

Сначала проверь, какая база используется: `XUI_DB_TYPE` в `/etc/default/x-ui`.
Если там `postgres`, файл `/etc/x-ui/x-ui.db` может быть старым, и его копия ничего не защищает.
В этом случае нужен дамп. Кнопка обновления в панели его не делает, поэтому сними его заранее:

```bash
set -a; . /etc/default/x-ui; set +a
pg_dump -Fc -f /root/xui.pgdump "$XUI_DB_DSN"
```

Копии базы и файла `/etc/default/x-ui` содержат ключи клиентов и пароль от базы.
Храни их с правами только для root и удаляй после проверки.

Если панель привязана к домену, запрос к `127.0.0.1` вернёт `403`, это не поломка.
Проверяй панель и подписку по доменному имени.

## Обновление на новый релиз upstream

```bash
scripts/fork-sync.sh v3.12.0
```

Скрипт сливает релиз, заново применяет настройки форка и выставляет версию `3.12.0-oidc.1`.
Конфликты в файлах OIDC решаются вручную. Затем:

```bash
(cd frontend && npm ci && npm run gen) && cp frontend/public/openapi.json docs/public/openapi.json
go test ./...
git add -A && git commit
git tag v3.12.0-oidc.1 && git push origin main v3.12.0-oidc.1
```

Тег запускает сборку. Когда соберутся все платформы, релиз становится последним,
и панели начинают предлагать обновление.

Для исправления только в форке увеличь последний номер в `internal/config/version`
(например, `3.12.0-oidc.2`) и выпусти тег с таким же номером.

После слияния проверь изменения upstream вокруг кода OIDC: `ClientService`, сессии, вход и настройки.
Компилятор не покажет смену поведения. Так, в 3.11 `Create` сбрасывает `LimitHwid`, поэтому
для привязки существующих клиентов используется `Attach`.

Кнопкой GitHub «Sync fork» не пользуйся: она тянет ветку `main` upstream, а не стабильный релиз.
